# Contract v1 (implementation baseline)

Approved scope: Codex project coordination; DSH Flash-default bounded coding/investigation/review/integration; explicit model routing and skill layers; structured task handoff; risk-based understanding gate; durable task/attempt identity, idempotency, bounded waits, recovery and cancellation; isolated Git workspaces, review tied to exact commit and controlled integration; owned-session retention/cleanup. No automatic model fallback, arbitrary-user-session adoption, credential disclosure, or recursive delegation.

Language/runtime: Node 24 ESM and node:test, built-ins only. Exports below are stable. Throw Error with `.code` for domain failures. Objects crossing boundaries are JSON-serializable. Timestamps are integer epoch milliseconds. All public inputs are untrusted and validated. State is host-owned; model assertions never supply execution evidence.

## TaskPacket
Required: `schemaVersion:1`, `idempotencyKey` (nonblank <=200), `revision` (positive integer), `projectId`, `title`, `objective`, `cwd` (absolute existing directory), `role` (`investigate|implement|review|integrate`), `acceptance` (nonempty string array), `scope` `{readRoots:string[],writeRoots:string[],allowedTools:string[],allowShell:boolean,allowNetwork:boolean,allowDelegation:false}`, `materials` array of `{path?,text?,version?,sha256?}`, `contractVersion` string.
Optional: `parentTaskId`, `dependencies:string[]`, `model` `{provider,model,reasoningEffort?}`, `budget` `{timeoutMs,maxToolCalls,maxOutputChars}`, `understandingRequired:boolean`, `workspace` `{repository,baseRef,branchName?}`, `retention` `{successDays,failureDays}`, `metadata` plain object. Missing model uses Flash default. Missing budgets default to 600000ms, 100 calls, 200000 chars; these are requested constraints and MUST NOT be reported hard enforced without corresponding runtime support.

## Controller identity (p0b-v1)

Every authenticated bridge request carries a request-local principal `{id, admin}` selected exclusively by its bearer credential. `task.submittedBy` stores that principal at submission and is immutable; the existing `owner` keeps its resource-ownership meaning. A delegate inherits its root controller's effective non-administrator credential, so its tasks belong to that root principal; `via:{chain,rootTask}` records client-declared submission provenance and grants no authority (it is excluded from the idempotency hash). Accepted limitations of the cooperating-agent threat model: a delegate can mutate other tasks of the same root principal, sessions sharing one controller ID share authority, and final acceptance remains the root controller's responsibility. Shared-user filesystem access and deliberate credential theft are outside the boundary. Before spawning a delegate the peer server resolves one effective token once, verifies a non-administrator controller identity with that exact token, and refuses an administrator credential before spawn; under contract R2 an unreachable bridge, a failed capabilities call or an unverifiable identity starts the delegate with `DSH_BRIDGE_DISABLED=1` and no bridge credential (job `bridge:{state:"disabled",reason:"<code>"}`), while a delegated marker or multi-member chain without an environment token refuses local-file fallback.

Host config adds `controllers` (required array, 1–32) and `identityMigrationBackupDirectory` (absolute local directory, required to migrate an existing v0 store). Each controller item allows only `{id, tokenFile, admin?}`: `id` is unique and matches `^[a-z][a-z0-9-]{0,63}$`; `tokenFile` is an absolute local readable path; its trimmed UTF-8 content must be 24–512 printable ASCII characters with no internal whitespace and must be unique; `admin` defaults to false. Malformed configuration, duplicate IDs/tokens or weak tokens are `CONTROLLER_CONFIG_INVALID`; an unreadable file is `AUTH_UNAVAILABLE`; an unset/lost caller context is `AUTH_UNAVAILABLE`. Top-level `token`, `credentialFile` and `tokenEnv` are refused when present. Only token digests are retained in the authentication closure.

Every tool declares exactly one category: **6 read** (`bridge_check`, `bridge_result`, `bridge_dossier`, `bridge_list`, `bridge_models`, `bridge_capabilities`), **1 submit** (`bridge_submit`), **13 mutate** (`bridge_approve`, `bridge_clarify`, `bridge_followup`, `bridge_cancel`, `bridge_pause`, `bridge_resume`, `bridge_reconcile`, `bridge_acknowledge`, `bridge_archive`, `bridge_cleanup`, `bridge_workspace_review`, `bridge_workspace_refresh`, `bridge_workspace_integrate`). A missing/unknown category or duplicate name is `TOOL_POLICY_INVALID` at construction/mount. Read tools have no ownership check; submit binds the authenticated principal. Mutations require matching `submittedBy`, or an administrator supplying top-level `override:{reason}` on a mutate tool only. Non-administrator override or any override on read/submit is `OVERRIDE_NOT_PERMITTED`; an administrator on a foreign or historical task without a reason is `OVERRIDE_REASON_REQUIRED`; a non-administrator on such a task is `TASK_NOT_OWNED`; a missing target is `TASK_NOT_FOUND`. A reason is a string of raw length ≤500, nonblank after trim, stored trimmed. Override does not bypass any existing lifecycle, revision, attempt, workspace or retention gate. A `task/override` intent event (operationId, actor, submittedBy, tool, reason, revision, attemptId, via) is durable before execution and a linked `task/override-result` (outcome `returned|threw`, post-call attemptId, and the fields of **this operation's own outcome**, chosen per tool: cancel/pause/resume read their nested result and every cancel branch returns one `cancel` shape; clarify and follow-up record only `replay`; approve, reconcile, clarify and follow-up never copy the task-level `accepted`; acknowledge and workspace_integrate keep their business `accepted`; `code` comes only from the operation, never from a historical task error) follows; intent failure is `OVERRIDE_AUDIT_FAILED` with no business call, result failure is `OVERRIDE_AUDIT_INCOMPLETE`, and an interrupted intent means an unknown outcome until inspected. No async wait is inserted before the synchronous clarify/followup entry point. Historical tasks retain `submittedBy:null` and require an administrator plus override reason to mutate. `bridge_list.submittedBy` is omitted (all), a valid controller ID (that principal, including retired IDs) or null (historical). `bridge_capabilities.controllerIdentity` returns `{enabled:true,schemaVersion:1,self,admin,controllers(sorted IDs),ownership:'credential-principal',delegation:'inherit-root-credential',legacyTaskOwner:null,override:{requiredForForeignTasks:true,reasonMaxChars:500},via:{source:'client-declared',authorizes:false}}` with `self`/`admin` from the request context; no token or token path is exposed.

The HTTP entry authenticates first, parses the envelope, then validates `X-Agent-Bridge-Chain` (1–5 members from `claude-code|codex|dsh`, joined by `>`, ≤256 bytes) and optional `X-Agent-Bridge-Root-Task` (`^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`, chain required); duplicate headers, control characters, a root task without a chain or a malformed value are `VIA_INVALID` with HTTP 400. Root controllers send no via headers (`via:null`, contract R1); only delegates send them. The first submission's `via` is never overwritten; the value is client-declared and does not authorize. When Claude Code is the delegate (`claude-code` target in delegate mode), the peer server generates exactly the plugin's two MCP entries and starts it with `--strict-mcp-config`, excluding the user's other MCP servers; a Codex delegate keeps its own MCP configuration and is not subject to that two-entry exclusion. `bridge_cleanup` ownership is checked even for `dryRun:true`; workspace dispatchers authorize before mutating or clearing a review.

The task store moves `user_version` 0 → 1 with `tasks(id,owner,submittedBy,idem,hash,body,UNIQUE(owner,submittedBy,idem))`. Historical rows use the SQL namespace `""` and body `submittedBy:null`; controller IDs cannot be empty. A new empty store is created at v1 without a backup. An existing `user_version=0` store must match the shipped v0 schema (`tasks(id,owner,idem,hash,body,UNIQUE(owner,idem))`, no `submittedBy`, plus the shipped events objects); a `user_version=1` store must match the shipped v1 schema above (`submittedBy` present, `UNIQUE(owner,submittedBy,idem)`); a version/shape mismatch — including `user_version=0` with the v1 table shape — is `STORE_SCHEMA_UNSUPPORTED` and is neither migrated nor repaired. An existing v0 store requires `identityMigrationBackupDirectory`: `VACUUM INTO` a consistent snapshot including committed WAL, integrity-check and fsync it (`STORE_BACKUP_FAILED` stops the mount if this fails), then in `BEGIN IMMEDIATE` create `tasks_v1`, copy rows in old rowid order while preserving id/owner/idem/hash/packet/all rounds, add `submittedBy:null`/`via:null`, verify row count/identity/uniqueness, replace the table, set `user_version=1` and commit; a transaction failure rolls back and refuses the mount with `STORE_MIGRATION_FAILED`, retaining the backup. Unknown versions/shapes are `STORE_SCHEMA_UNSUPPORTED`. Existing v1 is not migrated again. All update/beginAttempt/beginRound/clarify/followup paths preserve `submittedBy`/`via` (violations are `IMMUTABLE_IDENTITY`); internal supervisor workers use the parent's `{submittedBy,via}` and parent/child `submittedBy` consistency, so packet metadata or `parentTaskId` cannot grant authority. Idempotency is namespaced by `(owner,submittedBy,idem)`: same key/packet/principal reuses, a different packet conflicts, a different principal is independent, and `via` changes never affect it. Legal/operational detail: [docs/controller-identity.md](docs/controller-identity.md).

## S4 contract revisions (R5–R7)

**R5 — Claude delegate strict MCP.** When Claude Code is the delegate (including Codex → Claude), the peer server's invocation builder generates exactly the plugin's two stdio MCP entries (`plugin_agent-bridge_dsh_project` → `bin/bridge.mjs`; `plugin_agent-bridge_agent_peer` → `bin/peer-mcp.mjs` with `AGENT_BRIDGE_SELF=claude-code`) and starts it with `--strict-mcp-config`; no HTTP entry and no user-configured MCP server is included, so the user's other MCP servers are deliberately excluded. This is kept even when the bridge is unavailable or the delegate runs disabled under R2 (`DSH_BRIDGE_DISABLED=1`, no credential): the disabled marker, inherited credential and `via` are honoured only by the carrier and the credential resolver, so relaxing strict would let the disabled state leak through another MCP path and make the tool surface depend on bridge health. Compatibility impact: a Claude delegate workflow that depended on the user's other MCP servers loses those tools and must be planned for in the upgrade. A Codex delegate keeps its own MCP configuration with the forwarded credential/chain environment; the two-entry strict exclusion is not claimed for it (known, accepted asymmetry).

**R6 — Test temporary directories.** The controller-identity tests (`test/controller-*.test.mjs`, `test/test-root.test.mjs`) obtain temporary directories through `test/helpers/test-root.mjs`; older suites still use `os.tmpdir()`, which local acceptance also points under `F:	emp` by setting `TEMP`/`TMP`. It accepts an explicit `BRIDGE_TEST_TMP` as the base (it must be absolute; it is created if missing; each test gets its own unique subdirectory and removes only that subdirectory); when `BRIDGE_TEST_TMP` is unset it uses `os.tmpdir()`. Local acceptance commands set `BRIDGE_TEST_TMP`, `TEMP` and `TMP` to `F:/temp/agent-bridge-upstream/test-tmp`; CI sets `BRIDGE_TEST_TMP` to the runner's temporary directory. Test code must not hardcode a drive letter or choose a directory by testing whether a path exists. Migration backups and disposable upgrade artifacts remain under `F:/temp/agent-bridge-upstream` outside git worktrees.

**R7 — File ownership.** Ownership is exclusive; a package that must touch a file outside its list stops and returns the call-chain evidence to the root controller for reassignment (R4). ## Models / context module (src/models.mjs and src/context.mjs)
`resolveModel({user,task,project,defaults,catalog,profiles})` returns `{provider,model,reasoningEffort?,profileId,profileVersion,skillIds:string[]}`. First defined complete route wins user > task > project > defaults (Flash default if absent); reject incomplete route/unknown route/unsupported explicitly provided effort when catalog advertises efforts. catalog is array `{provider,models:[{id,reasoningEfforts?:string[]}]}`. profiles array `{id,version,provider,model,skillIds?:string[],roles?:string[]}`. No silent fallback. Return detached values.
`buildPrompt(packet,{model,skills=[]}={})` returns text preserving scope, sources as untrusted materials, precise acceptance, fact/inference/unknown distinctions, no recursive delegation, owner coordination; understanding gate instructs return understanding/assumptions/actions/missing without executing. ## Workspace module (src/workspaces.mjs)
`WorkspaceManager({root,git='git'})` with async `create({taskId,repository,baseRef,branchName?})` -> `{taskId,path,branch,baseCommit,repository}`, `inspect(workspace)` -> `{head,dirty,changedPaths}`, `review(workspace,{head,contractVersion,passed,checks})` -> immutable review record. `integrate(workspace,{targetRepository,review,contractVersion,checks=[]})`: refuse dirty source/target, mismatched head/contract, target not equal base (caller must rebase and re-review), failed review. Run supplied checks as `{command,args}` without shell in source and target as appropriate; use fast-forward-only merge after verification; if target check fails do not misreport accepted. Return exact head/check evidence. `remove(workspace,{artifactState,pinned=false})`: only manager-owned path inside root, no dirty/uncollected changes; artifactState `merged|preserved|discarded` required; native git worktree remove only, never arbitrary recursive deletion. Implement ownership persistence under root. No caller-controlled raw command strings.

## Retention policy module (src/retention-policy.mjs) - isolated comparison
Pure export `evaluateRetention(task, policy, now)` -> `{eligible:boolean,reasons:string[],eligibleAt:number|null}`. No mutation, I/O, clock reads. policy `{ownerId,successDays:7,failureDays:30}`. Owned task requires exact nonblank `task.ownerId===policy.ownerId`, task `origin==='codex-bridge'`, nonblank `task.id`; permitted terminal states `completed|failed|cancelled`; integer nonnegative `endedAt<=now`; `resultCollected===true`; `pinned!==true`; `stopConfirmed===true`; `activeJobs===0`; `artifactState` one of `none|merged|preserved|discarded`. Unknown/in-flight/unconfirmed/malformed must fail closed. Duration days finite nonnegative; now integer nonnegative. completed uses successDays, others failureDays; expiry inclusive. Reasons are stable machine strings, include all applicable blockers in this fixed order: invalid_policy, invalid_time, foreign_owner, invalid_identity, nonterminal, invalid_end, uncollected, pinned, stop_unconfirmed, active_jobs, artifacts_unresolved, retention_pending. `eligibleAt` = valid endedAt + valid retention duration (safe integer) only when status, endedAt, policy and now valid, otherwise null. Invalid/overflow policy duration -> invalid_policy. Evaluate nonobjects as empty objects. `activeJobs` MUST equal numeric 0 (no coercion). Missing artifactState blocks. Invalid result collection / stop confirmation values block. For malformed now, invalid_end only when endedAt itself malformed; future-ended comparison applies only if now valid. Unknown status => nonterminal and eligibleAt null. Empty/missing policy ownerId => invalid_policy AND foreign_owner. Whitespace ids invalid. pinned false/absent accepted; nonboolean supplied pinned => pinned (fail closed). Unknown extra fields ignored.

## DSH adapter seam (coordinator / adapter worker)
Runtime adapter exposes async `capabilities()`, `models()`, `start(task,{onEvent,onResult})`, `continue(task,understanding,{onEvent,onResult})`, `cancel(task)`, `inspect(task)`, `cleanup(task)`. All return JSON objects; start yields `{sessionId,requestId,effectiveModel,effectivePolicy}`. Events contain type, timestamp, taskId, revision, attemptId, seq when available. Cancellation returns `{accepted,stopConfirmed,remaining:[]}`; host cancel alone is never confirmation. Runtime worker must document actual installed DSH hook/API support, and fail closed if requested scope cannot be enforced. Never fake hidden/cleanup support.

## Follow-up lifecycle (`bridge_followup`)

`bridge_followup {taskId,revision,afterAttemptId,followupId,text}` continues ONE settled read-only task in its existing owned session. `BridgeService.followup(id,{revision,afterAttemptId,followupId,text})` is synchronous: validate the arguments, read the task, answer an idempotent replay from persisted history (returning the current view with `followup:{...,replay:true}`), then refuse with `FOLLOWUP_UNSUPPORTED` when `adapter.followup` is absent, `CLEANUP_BUSY` while archive/cleanup holds the task, and `SESSION_NOT_READY` while a dispatch is pending; it builds the fenced prompt once, calls `TaskStore.followup`, kicks the shared drain and returns the view plus the follow-up block. `onEvent` takes the tool-call baseline from the current entry's `baselineToolCalls`, so each round's accounting starts at its own base. `followupRequestHash({revision,afterAttemptId,followupId,text})` digests exactly those fields without trimming. `TaskStore.followup(id,{followupId,text,revision,afterAttemptId})` runs one transaction: replay lookup first (same `followupId` and hash => `{created:false,task,entry}`, different hash => `FOLLOWUP_IDEMPOTENCY_CONFLICT`), then eligibility in error-table order — role `investigate|review`; not `packet.project`/`task.project` and not `packet.metadata.supervisorProject`; an understanding gate (`understandingRequired===true`) requires `executionApproved===true`; `revision` and `afterAttemptId` equal the current values; terminal `completed|failed|cancelled`; no `sessionArchivedAt`/`archivedAt`; `stopConfirmed===true` with integer `activeJobs===0` and `activeChildren===0`; `dispatchPending!==true` with a nonblank `sessionId`; and the session binding rule below — then writes the entry, mints the new attempt state and emits `task/followup-requested {revision,afterAttemptId,attemptId,followupId,round}`.

The persisted `followups[]` entry is copied field by field (never whole nested records): `{followupId,requestHash,text,revision,afterAttemptId,attemptId,round:(task.followups?.length??0)+1,createdAt,baselineToolCalls:task.stats.toolCalls,previousAttempt:{attemptId,attempt,revision,sessionId,requestId,phase,status,continuationKind,dispatchReceiptAt,startedAt,endedAt,effectiveModel,stopConfirmed,activeJobs,activeChildren,result,error,stats,resultCollected,accepted,dispatchFailure},boundAttempt:{attemptId,requestId,sessionId,revision,effectiveModel,status,stopConfirmed,settlementEvidence}}`; `settlementEvidence` is the `source==='dsh-host' && kind==='attempt-settlement'` entries of `result.evidence`, retained to recompute `confirmedCancellation` on recovery. The new attempt mints `attemptId`, increments `attempt`, appends `attemptHistory`, sets `continuationKind:'followup'`, `status/phase:'queued'`, `dispatchStarted/dispatchPending:false`, `dispatchReceiptAt/requestId/startedAt/endedAt:null`, an empty `result`, `error/dispatchFailure/cancellationRequested/cancelError/cancelRemaining/recovery:null`, `resultCollected:false` and `accepted:false`, and keeps the stop true/0/0. Preserved: `packet`, `effectivePacket`, `requestHash`, `revision`, `sessionId`, `workspace`, `effectiveModel`, `executionApproved`, `artifactState`, `pinned`, the callback binding, `clarifications` and previous `followups` entries. A late callback from a superseded attempt never mutates the new one.

`DshAdapter.followup(task,hooks)` shares the private `#reopenSession(task,hooks,variant)` with `reconsider` (clarification). The follow-up variant is `{continuation:'followup',mode:'execution',noun:'follow-up attempt'}`; `reconsider` keeps `{continuation:'clarification',mode:'understanding',...}` and its outward behaviour and messages unchanged. Variant differences: an existing attempt must carry the same `continuation`, else `adapter/attempt-conflict`; a new attempt is minted with `attempt.continuation:'followup'` and `attempt.roundBudgetBase:record.toolCallsAdmitted`; recovery binds only through `#persistedFollowupBinding(ref)` — the `followups` entry with `attemptId===ref.attemptId` and its `boundAttempt`, with owner/origin/revision checked like the previous-attempt resolver, and a missing or incomplete binding is `adapter/recovery-unsafe` (`dispatched:false`) — and `#recoverTask` keeps `mode:'execution'` when `ref.continuationKind==='followup'`; `ref.prompt` must be a nonblank controller-built string, else `adapter/invalid-packet` (`dispatched:false`); `#resolveEnvelope` passes `followups` and `continuationKind` through. `buildFollowupPrompt(packet,{taskId,round,followupId,text})` is a trusted header (task id, round, stay inside the original objective/scope/authority, answer from this session, report a range conflict instead of executing) plus the question rendered as fenced untrusted material with the existing material-delimiter validation; scope, materials and skills are not resent. Session binding at mint (its absence is `SESSION_NOT_READY`): use the current attempt's persisted dispatch receipt (`requestId` nonblank and finite `dispatchReceiptAt`); otherwise only when the current attempt never crossed the host boundary (`dispatchStarted!==true`, i.e. cancelled or interrupted before dispatch, or `dispatchFailure.dispatched===false && dispatchFailure.attemptId===task.attemptId`) and a `followups` entry with `attemptId===task.attemptId` carries a `boundAttempt`, reuse that `boundAttempt`; neither satisfies the rule => `SESSION_NOT_READY`. A child session in a follow-up round is admitted with `record.toolCallsAdmitted - (Number.isInteger(attempt?.roundBudgetBase)?attempt.roundBudgetBase:0) >= sharedCap`, so the shared cap is charged from this round's per-attempt base rather than the lifetime count.

Error codes: `INVALID_ARGUMENTS` (shape/type/blank/oversize/extra field), `TASK_NOT_FOUND` (unknown or foreign task), `FOLLOWUP_IDEMPOTENCY_CONFLICT` (`followupId` bound to different content), `FOLLOWUP_ROLE_FORBIDDEN` (role not `investigate|review`), `FOLLOWUP_UNSUPPORTED_TASK` (project task, project worker, or `understandingRequired===true && executionApproved!==true`), `FOLLOWUP_CONFLICT` (revision or `afterAttemptId` mismatch, or non-terminal), `FOLLOWUP_ARCHIVED` (`sessionArchivedAt` or `archivedAt` set), `SESSION_NOT_READY` (stop not true/0/0, no `sessionId`, pending dispatch, no usable binding), `FOLLOWUP_UNSUPPORTED` (adapter lacks the method), `CLEANUP_BUSY`, `material_delimiter_conflict` (fence validation). Dispatch-time adapter refusals keep their `adapter/*` identity (`not-owned`, `packet-changed`, `model-route-mismatch`, `attempt-conflict`, `attempt-in-flight`, `task-cleaned`, `task-archived`, `recovery-unsafe`, `host-state-unknown`, `host-not-settled`), travel with `dispatched:false`, mark that attempt `failed` with `dispatchFailure`, keep the previous answer in history, and allow a later follow-up whose `afterAttemptId` is the failed attempt's id. `capabilities().lifecycle.followup` reports `{supported:true,mode:'execution',roles:['investigate','review'],session:'existing owned session only',model:'reuses the bound route',budget:'each follow-up gets the original packet budget (per-attempt base)',excludes:['packet.project','project workers','unapproved understanding gate'],recovery:'followups[].boundAttempt only; a cold host restart with no live agent is refused (guarded-agent-absent)',limits:{followupIdMaxChars:200,textMaxChars:20000}}`; its `gates` are the same host/ownership/session gates as `lifecycle.reconsider`, plus the terminal true/0/0 stop.

`BridgeService.result(id,{offset,limit,attemptId})` reads the current round when `attemptId` is absent and the saved snapshot of a previous round when it equals that round's attempt id; any other id is `ATTEMPT_NOT_FOUND`. It keeps the existing slice fields and adds `round` (0 = original) and `followupId` (null for the original attempt). `view()` excludes full snapshots and adds `round` plus a compact `followups` list; `dossier()` adds the current `attemptId` and `rounds` (ascending, current last, question bounded to 4000 characters with the full length in `questionChars`). `bridge_acknowledge` and `bridge_archive` keep their interfaces and act on the current round. Peer closeout: when `dossier.rounds.length>1`, call `resultText(taskId,{attemptId})` per round, passing and validating the attempt id on every page (a mismatch throws), record `rounds:[{round,attemptId,followupId,question,status,resultText}]`, keep `resultText` as the current round for old renderers, hash that task as `${taskId}@${dossier.attemptId}` only for multi-round tasks (single-round hashes unchanged), and render every round's question and answer. The peer sweeper collects every `(harness,id)` referenced by a not-yet-due record (`eligibleAt` not finite or `> at`) or a `keep===true` record before acting; a due record whose session is still referenced performs no action and reports `{action,state:'skipped',note:NOTE_SESSION_STILL_REFERENCED}`.

## Coordination and tests
Root owns contracts, task store, orchestration, HTTP/MCP and packaging. Workers own only explicitly assigned module/tests. Every test invocation must finish within a bounded task budget. No unrelated live-host restarts. Benchmark branches have the SAME task, code baseline and acceptance tests; do not inspect other candidate implementations. First-pass and repair results are separate. Verify actual model/effort from runtime records. No general model ranking from one module.

## Long-task supervisor (`packet.project`) — long-supervisor-first-edition-v1
Optional additive grant on `bridge_submit` (advertised in the packet schema; reported by `bridge_capabilities.supervisorProjects`). Absent => the historical single bounded task, byte-identical. Host policy `supervisorProjects.enabled` defaults to `false`; when it is not true a `project` packet is refused (`PROJECT_UNSUPPORTED` / `adapter/project-unsupported`) before any task, session or worktree exists. Host caps (16 workers, 2 repair attempts, 64 starts/retries, 15 reserved slots, 86400000 ms) are ceilings: a larger request is refused (`PROJECT_HOST_CAP`), never clamped.

`src/contracts.mjs` validates and normalizes the block: `{maxWorkers,maxConcurrentWorkers,maxRepairAttempts<=2,maxTotalRetries,maxWorkerStarts,maxTotalToolCalls,timeoutMs,reserveSlots,workerScope{readRoots,writeRoots,allowedTools,allowNetwork,budgets?},workspace{repository,baseRef}?}`. A project packet must declare `scope.writeRoots: []` and must not grant `scope.childSessions`/`scope.backgroundJobs`; `understandingRequired` is refused; with `workspace`, every worker root and `cwd` must stay inside the repository so a per-writer worktree really isolates them.

`src/long-task.mjs` owns the runtime: `createProjectRecord` is persisted WITH the task before any dispatch; `resolveProjectGrant` enforces host caps; `attenuateWorkerRequest` refuses (never clamps) any worker widening and always fixes the worker route to the project's inherited model; `aggregateProject` is the pure completion/retry/failure gate (`attempt.retryBlocked` = exhausted; a controller cancellation is never retryable); `projectCallbackEventId` binds a stable identity to (task, attempt, outcome class, aggregate). Statuses: `planning|frozen|dispatching|completed|failed|blocked|cancelled`, plus the non-terminal task status `supervising` while a project waits between rounds. Only verified stopped owned work may produce a terminal `completed`/clean `failed`; unverified work => `project.status:'blocked'`, task status `unknown`, `stopConfirmed:false`, reservations held, no redispatch. `admitProject`, called once by `src/service.mjs` immediately after the project task is persisted and before any dispatch, arms the single LIVE project deadline from `project.createdAt` and clamps the supervisor's EFFECTIVE packet budget to the grant while `task.packet` and the stored request hash stay immutable (a later dispatch clamps the effective timeout to the remaining project wall time). The shared tool cap uses one canonical accounting counted once (supervisor observed spend + each stop-proven attempt's actual spend + each unverified attempt's full granted allowance); missing/unreadable receipts keep their full allowance, a temporary reservation makes a queued worker wait rather than fail, and no clean completion/failure/cancellation is recorded without supervisor-round AND every-owned-attempt stop proof. `src/dsh-adapter.mjs` registers six `dsh_supervisor_*` tools into the authorized supervisor's own scoped layer only when the grant is present, admits them by grant (naming them in `allowedTools` is refused), and keeps them out of every worker/child. `src/supervisor.mjs` adds the durable `notifyProjectOutcome` (one event per outcome class; a serious issue never claims a stop). `src/service.mjs` releases only the supervisor's own model reservation at a positively stopped round, drives the runtime from settlement hooks, and branches project tasks in `finish/cancel/recover/reconcile/wait`. Shutdown closes the runtime before the outbox. Evidence: `test/long-task.test.mjs`, the additions to `test/dsh-adapter.test.mjs`, and the real offline `scripts/smoke-supervisor.mjs` with `test/fixtures/supervisor-provider.mjs`.
