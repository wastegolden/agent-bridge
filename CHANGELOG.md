# 1.8.0 — controller identity and `bridge_followup` (2026-11-04)

## Controller identity (`p0b-v1`)

- Per-controller bearer credentials: host `controllers` (1–32 entries, `id` matching `^[a-z][a-z0-9-]{0,63}$`, absolute `tokenFile`, optional `admin`, default false) replaces the shared token. Token files must hold 24–512 printable ASCII characters with no internal whitespace; duplicate or weak tokens and duplicate IDs refuse the mount (`CONTROLLER_CONFIG_INVALID`), an unreadable file is `AUTH_UNAVAILABLE`. The old top-level `token` / `credentialFile` / `tokenEnv` keys are refused whenever present. Only token digests stay in the authentication closure.
- `task.submittedBy` is written from the authenticated request principal and is immutable across submission, update, attempt minting, clarification, follow-up and supervisor rounds; internal supervisor workers inherit the parent's `{submittedBy, via}`. `ownerId` keeps its resource-ownership meaning. Same idempotency key is namespaced by `(ownerId, submittedBy, idempotencyKey)`: different controllers get independent tasks, a different packet for the same principal is `IDEMPOTENCY_CONFLICT`.
- Every tool is exactly one category: **6 read** (`bridge_check`, `bridge_result`, `bridge_dossier`, `bridge_list`, `bridge_models`, `bridge_capabilities`), **1 submit** (`bridge_submit`), **13 mutate** (`bridge_approve`, `bridge_clarify`, `bridge_followup`, `bridge_cancel`, `bridge_pause`, `bridge_resume`, `bridge_reconcile`, `bridge_acknowledge`, `bridge_archive`, `bridge_cleanup`, `bridge_workspace_review`, `bridge_workspace_refresh`, `bridge_workspace_integrate`); a missing/unknown category or duplicate name is `TOOL_POLICY_INVALID`. Read tools have no ownership check; submit binds the principal.
- Administrator override is a top-level `override:{reason}` on a mutate tool only. Non-owner → `TASK_NOT_OWNED`; administrator on a foreign/historical task without a reason → `OVERRIDE_REASON_REQUIRED`; non-administrator override or any read/submit override → `OVERRIDE_NOT_PERMITTED`; malformed override → `INVALID_ARGUMENTS`; unknown task → `TASK_NOT_FOUND`. The reason is at most 500 raw characters, nonblank after trim, stored trimmed. Override does not bypass lifecycle, revision, attempt, workspace or retention gates.
- Override is audited durably: `task/override` intent (`operationId`, actor, submittedBy, tool, reason, revision, attemptId, via) is written before the business call, and a linked `task/override-result` (`outcome:"returned"|"threw"`, post-call attemptId, applicable accepted/merged/archived/cleaned/eligible/replay/code) after it. Intent failure is `OVERRIDE_AUDIT_FAILED` with no business call; result failure is `OVERRIDE_AUDIT_INCOMPLETE`; an interrupted intent means an unknown outcome until inspected. No async gap is added before the synchronous follow-up/clarification entry.
- Client-declared `via` from `X-Agent-Bridge-Chain` (1–5 harness names, ≤256 bytes) and optional `X-Agent-Bridge-Root-Task` (`^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`, chain required): stored as `{chain,rootTask}` or `null`, immutable after the first submission, excluded from the idempotency hash, and granting no authority. Invalid headers are HTTP 400 `VIA_INVALID`. Root controllers send no via headers (contract R1); only delegates send them. `bridge_capabilities.controllerIdentity` reports request-local `self`/`admin`, sorted `controllers`, `ownership:"credential-principal"`, `delegation:"inherit-root-credential"` and `via:{source:"client-declared",authorizes:false}`.
- Task-store migration: `user_version` 0 → 1 with `tasks(id,owner,submittedBy,idem,hash,body,UNIQUE(owner,submittedBy,idem))`. Historical rows keep `submittedBy:null` with SQL namespace `""`; the controller ID pattern excludes `""`, so the temporary `legacy` controller cannot collide with history. An existing v0 store requires `identityMigrationBackupDirectory`: `VACUUM INTO` a snapshot including committed WAL, integrity-check and fsync it (`STORE_BACKUP_FAILED` stops the mount), then a `BEGIN IMMEDIATE` copy with row/identity/uniqueness verification, table replacement and `user_version=1`; failure rolls back and refuses the mount (`STORE_MIGRATION_FAILED`). A new empty store (no schema objects) is created at v1 without a backup; an existing `user_version=0` store must match the shipped v0 schema (no `submittedBy`, `UNIQUE(owner,idem)`), an existing `user_version=1` store must match the shipped v1 schema, and any version/shape mismatch — including `user_version=0` on the v1 table shape — is `STORE_SCHEMA_UNSUPPORTED` rather than being migrated or guessed; an already-v1 store is not migrated again. Historical tasks stay readable by all principals but need an administrator plus override reason to mutate.
- Delegation: the peer server resolves one effective credential, verifies `controllerIdentity` with that exact token, and refuses an administrator credential before spawn (`PEER_BRIDGE_ADMIN_DELEGATION_FORBIDDEN`). Under contract R2 an unreachable bridge, a failed capabilities call or an unverifiable identity no longer blocks a delegate: the child starts with `DSH_BRIDGE_DISABLED=1`, no credential, and the job records `bridge:{state:"disabled",reason:"<code>"}` (never a token). Credential precedence is `DSH_MCP_TOKEN` → `DSH_BRIDGE_CREDENTIAL_FILE` → caller-configured file; a delegated marker or multi-member chain without an environment token refuses instead of falling back to a local file. Tokens never enter the invocation, `job.json`, prompt, argv or lineage ledger.
- Claude Code delegates now run with `--strict-mcp-config` and a generated MCP configuration containing only the plugin's two entries (`dsh_project`, `agent_peer`); the user's other MCP servers are deliberately excluded **only when Claude Code is the delegate**, including Codex → Claude. This is an explicit behaviour change from 1.7.0 and requires a two-direction disposable-task smoke test after upgrading: verify the two-entry surface on Codex → Claude, and verify inherited root identity/carrier plus a cheap DSH submission on Claude → Codex without claiming the Codex side excludes other MCP servers. The Codex template remains the stdio carrier `bin/bridge.mjs`; only the Claude root connects over MCP HTTP with the launch-environment token. Codex entries forward the credential/marker/chain variables and never statically override the inherited token.
- Threat model: accidental misuse by cooperating agents on one machine under one OS user. Accepted: a delegate may modify other tasks of the same root principal, sessions sharing a controller ID share permissions, and final acceptance remains the root controller's. Outside: shared-user filesystem access and deliberate credential theft.
- Upgrade/rollback: drain the whole host, stop, back up package/config/DB (including WAL/SHM)/events/clients and the live controller token files under `F:/temp/agent-bridge-upstream`, install the new package before the first restart, and merge the generated identity fragment (`controllers` + `identityMigrationBackupDirectory`) into the complete host config. Each root gets its own separate agent-peer config sharing one `stateDir` but pointing at its own `credentialFile`; Claude loads its token in the root launch environment, Codex clears the shared token and uses its own file, and the operator uses its own file. Run the first restart with an overlap config that keeps the temporary `legacy` administrator (every historical/foreign mutation uses an explicit override reason), run the dual-direction disposable-task smoke (two-entry Claude delegate on Codex → Claude; inherited identity/carrier on Claude → Codex, no Codex-exclusion claim), then a second restart with the final config that removes `legacy`; the old token must return HTTP 401. The pre-migration snapshot is a rollback point only before real new work; afterwards, real tasks require forward repair. Keep live controller token files and the needed backup snapshots; discard only intended test artifacts and the temporary legacy token. Operational detail: `docs/controller-identity.md` and the skill reference `bridge-lifecycle.md`.

## `bridge_followup`: bounded follow-up rounds in an existing DSH session

- New `bridge_followup` tool (`taskId`, `revision`, `afterAttemptId`, `followupId`, `text`): one bounded question to a settled read-only DSH task in its existing owned session. Only `investigate`/`review` tasks that ended `completed|failed|cancelled` with a confirmed true/0/0 stop are eligible; project tasks, project workers, an unapproved understanding gate, and archived or cleaned tasks are refused. The packet, workspace, session and model route are reused, so a follow-up cannot widen scope, tools, materials or budget.
- `afterAttemptId` (= the current `attemptId`) is the round CAS, because `revision` does not change between attempts; a stale id is `FOLLOWUP_CONFLICT` and mints nothing. `followupId` plus the exact request content is idempotent (same content replays the original attempt with `replay:true`, different content conflicts), and each round gets a fresh per-attempt budget equal to the original packet's.
- Older answers stay readable: `bridge_result` takes an optional `attemptId` to read a previous round's saved snapshot and returns `round` (0 = original) and `followupId`; `bridge_dossier` adds the current `attemptId` and per-round summaries (`rounds`); `bridge_check`/`bridge_list` add `round` and a compact `followups` list without expanding snapshots. `bridge_capabilities` reports `lifecycle.followup`.
- An adapter refusal at dispatch (existing `adapter/*` codes, `dispatched:false`) fails only that attempt and keeps the earlier answer; the controller can follow up again with a new `followupId` targeting the failed attempt. A cold host restart with no live guarded agent is refused (`guarded-agent-absent`), as with clarification.
- Fix: a child session in a follow-up round is charged against that round's per-attempt base (`roundBudgetBase`) instead of the lifetime tool-call count, so a legitimate child is no longer refused as exhausted at start.
- Fix: the peer sweeper skips a session still referenced by any not-yet-due or `keep:true` record (`state:'skipped'`, `NOTE_SESSION_STILL_REFERENCED`), so an expiring earlier record cannot archive or clean a session a later round still uses.
- Peer closeout records every round of a multi-round task: each round's question and answer, a per-round `resultText`, and a `taskId@attemptId` record hash only for multi-round tasks (single-round records are unchanged).
- Known limitations: a cold host restart without a live agent refuses the follow-up; a running attempt recovered after an adapter restart starts its budget count at 0 and measures timeout from session creation (a pre-existing limitation for every task); "complete memory" depends on the DSH host's own context retention/compression; the root `maxOutputChars` is not currently a hard limit.

## Repair 1 (candidate `dcd0bb55`) — budget, stop, cancel and dispatch hardening

- Stop proofs are strict: a missing or non-numeric `activeJobs`/`activeChildren` count is no longer coerced to zero. An unproven supervisor round or worker stop retains its reservation, blocks the project honestly and is never retried or reported as a clean terminal.
- The project tool-call cap is a RESERVATION held before every submit (full unspent allowance per attempt, supervisor round included) and released only with a verified stop, so parallel and queued attempts can never be promised the same remaining calls; spending above the bound never completes.
- `maxTotalRetries`/`maxWorkerStarts` are checked before an attempt is persisted or submitted, and unfundable queued workers settle as a clean failure instead of staying pending.
- The project deadline is anchored at `project.createdAt`, armed at admission (before `worker_create`), clamps each worker's runtime and converges live/queued work on real stop proofs; a hung planner no longer supervises forever.
- An unresolved supervisor cancellation keeps its model reservation; a `service.submit` failure after task insertion is resolved through the deterministic attempt key, links the real child and never fabricates a clean failure or a retry.
- `reserveSlots` minimum 1 is enforced in host config, packet schema/contracts and the grant; read-only worker roles attenuate inherited `writeRoots`; `maxConcurrentWorkers` follows a lowered `maxWorkers` as a dependent default while explicit contradictions stay refused; delayed settlements are merged by immutable attempt identity so no attempt result or dirty workspace proof is lost.
- Smoke teardown stops and proves the stop of its own unfinished tasks before terminating its own test host.

## Repair 2 (candidate `3a3da4a`) — real admission, receipts, canonical allowance, replay and unknown cancellation

- Real service ADMISSION: `BridgeService.submit` calls `SupervisorProjectRuntime.admitProject` exactly once after the project task is persisted and before any dispatch. It arms the single project deadline from the persisted `project.createdAt` and clamps the supervisor's EFFECTIVE `maxToolCalls`/`timeoutMs` to the grant; `task.packet` and the stored request hash stay identical. A later dispatch further clamps the effective timeout to the REMAINING project wall time.
- Deadline ownership is a LIVE timer: a persisted `deadlines.armed` flag from another process is never trusted, `#tick` consumes a fired expiry before the planning guard, and expiry cancels the actual supervisor round through the service plus live workers and converges from their stop callbacks instead of certifying a stop from the timer alone.
- Receipt and stale-snapshot losses are fixed: every start/refusal identity-merges the real `taskId`/`sessionId` onto the freshest persisted attempt by immutable attempt key, `onTaskSettled` links the real identity, and `#dispatch` re-reads fresh state for every decision, so all real submitted tasks appear in persisted attempts before aggregation/cancellation/recovery.
- One canonical allowance accounting: supervisor observed spend + each stop-proven attempt's actual spend + each unverified attempt's FULL granted cap, counted once. Missing/unreadable stats charge the full granted cap (never zero); a temporary reservation makes a queued worker wait for a verified-stop release instead of being permanently refused; budget refusals mark the already-failed prior attempt `retryBlocked` rather than fabricating a hiding attempt.
- `dsh_supervisor_worker_create` replay is idempotent against a frozen/running plan (same immutable worker, `idempotentReplay: true`) while a CHANGED definition for the same `workerKey` conflicts (`project/replay-conflict`).
- Reentrant settlement can no longer deadlock: `onTaskSettled`/expiry/timer hooks persist and merge immediately and enqueue the next transition without awaiting their own chain; only external `whenIdle` awaits a stable chain. `service.finish` on a project task also kicks the shared drain so a queued regular task is not starved.
- Unknown cancellation is never a clean terminal: the terminal `cancelled-unverified` paths are removed, so a cancellation that leaves unverified owned work stays task `unknown` / project `blocked`, `stopConfirmed:false`, reservations retained and still cancel/reconcile capable. `unknown` occupancy counts toward concurrency; a central guard requires supervisor-round AND every-owned-attempt stop proof before any clean completion/failure/cancellation.
- Smoke teardown now enumerates its own project tasks AND their sub-worker tasks, and a `host.stop()` failure can no longer mask the primary check result.
