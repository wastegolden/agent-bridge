# Bridge lifecycle (install, upgrade, uninstall)

The bridge itself is a DSH profile plugin. Its lifecycle is an operator action, not
part of task execution — a delegated worker never installs, upgrades, restarts or
uninstalls the bridge, because that reaches outside the task packet's authority and
affects every session on the host.

## Shape of an installation

- Package: `<profile>/node_modules/@local/dsh-codex-bridge-v1`
- Loader row: one `insert:` entry with id `dsh-codex-bridge-v1` in
  `<profile>/cordis.patch.yml`, pointing at that package.
- Installer state: `<profile>/node_modules/@local/.dsh-codex-bridge-v1/` holding
  `install-manifest.json` plus a `backups/` directory.
- Host entry: `dsh-host/index.cjs` inside the package (written by the project, not
  generated by the installer).

The installer never guesses a profile. Both the target profile and the package
source root are explicit arguments.

## Install

1. Plan first: `node scripts/install.mjs --profile <profile> --source <root> --dry-run`.
   The dry run validates and prints the full plan — files, exclusions, backup
   mappings, patch row — and writes nothing.
2. Validate: the source must contain `package.json`; the host entry is
   syntax-checked without being executed; symlinked content is refused; the tree is
   size-bounded.
3. Stage and copy: the source is copied through a staging snapshot into the package
   directory, with `.git`, `.runtime`, `.worktrees` and `evidence/raw` excluded.
   Pre-existing files that are replaced are backed up first.
4. Patch: exactly one owned insert row is appended, delimited by explicit start/end
   markers. Re-running the installer recognizes its own block and does not
   duplicate it; a foreign row with the same id is left untouched and reported.
5. Manifest: before/after SHA256 and the backup mapping are persisted.

## Uninstall

`node scripts/uninstall.mjs --profile <profile>` reads the manifest and:

- restores files whose content still matches what the installer wrote, from backup
  or by removing the file that did not exist before;
- reports a conflict and leaves the file alone when it was edited locally;
- preserves files it does not own, and removes directories only when they become
  empty;
- removes its own marker block from `cordis.patch.yml`, deleting that file only if
  the installer created it and nothing else is in it;
- refuses to act without a manifest, or with a manifest for a different profile.

`--dry-run` reports the same actions without changing anything.

## Boundaries

- No global configuration is touched: not `~/.codex`, not `~/.agents`, not agent
  files, not tokens, not environment variables. The installer refuses those paths.
- No arbitrary recursive deletion: files are unlinked individually and directories
  are removed only when empty.
- Mounting takes effect on the next host start. Neither script restarts the host;
  never restart a live host as part of a task.
- Failures roll back: a run that fails after planning undoes what it wrote and
  reports what it could not undo.
- When a reinstall, upgrade or uninstall is genuinely part of the work, it is a
  separate, explicitly authorized operator task with its own evidence — not a step
  hidden inside a coding task.
